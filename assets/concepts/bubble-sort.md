# Bubble Sort

你有一排身高亂七八糟的小朋友。老師說：「從矮排到高。」

不需要什麼聰明的方法：從頭開始，兩個兩個比。高的那個往右站。走完一趟，最高的那個一定在最右邊。

再走一趟。第二高的歸位。

再走一趟。第三高的歸位。

走到沒人需要換位置，就排好了。

這就是 Bubble Sort。大的數字像汽水裡的大氣泡一路被推到右邊，一輪浮一個，所以叫 bubble。

---

## 範例資料 `[2, 3, 1, 5, 4]`

這組資料幾乎排好了。1 站在 index 2，該站 index 0，偏了兩格；它前面的 2 跟 3 因此各往右多站一格。最後的 4 和 5 對調。

只有兩處要動，跑起來 3 輪就結束，比跑滿 5 輪短。

每跑完一輪，剩下還沒排好的數字裡最大的那個，就被推到線的最右邊，之後不再動。所以線一輪比一輪短，右邊的深色一輪比一輪長。

## 程式碼

```typescript
function bubbleSort(nums: number[]) {
  const n = nums.length;
  for (let i = 0; i < n; i++) {
    for (let j = 0; j < n - 1 - i; j++) {   // 右邊已排好，每輪少比一個
      if (nums[j] > nums[j + 1]) {
        [nums[j], nums[j + 1]] = [nums[j + 1], nums[j]];
      }
    }
  }
}
```

### 外層迴圈：跑幾輪？

`for i := 0; i < n; i++`。最多跑 n 輪。每一輪至少把一個元素推到它最後的位置，所以 n-1 輪就夠了，剩下那一格自己就在對的地方。這裡寫成 n 只是多跑一輪空的，不影響結果。

### 內層迴圈：每輪比到哪？

`for j := 0; j < n-1-i; j++`，`n-1-i` 決定每輪比到哪：第一輪比到倒數第一個，第二輪比到倒數第二個，因為右邊已經排好了，不用再看。

為什麼是 `n-1` 而不是 `n`？因為每次比的是 `nums[j]` 和 `nums[j+1]`，j 跑到最後一個的話 `j+1` 就超出陣列了。

### 交換

`nums[j], nums[j+1] = nums[j+1], nums[j]`。左邊比右邊大就交換，bubble sort 全部的動作就是這一行。

### 排好了還是繼續跑

上面那份 code 排得對，但把 `[1, 2, 3, 4, 5]` 丟進去看看：

```
第 1 輪  比 4 次  一次都沒換
第 2 輪  比 3 次  一次都沒換
第 3 輪  比 2 次  一次都沒換
第 4 輪  比 1 次  一次都沒換
```

第 1 輪走完，資訊已經足夠了：每一對相鄰的都是小的在左邊，那整條就是排好的。上面那份 code 沒有把這件事記下來，所以第 2 輪又從頭掃一次，掃出同樣的結論，再掃第 3 輪、第 4 輪。

n = 5 的時候多比 6 次，不痛不癢。n = 10,000 的話，第 1 輪比 9,999 次就能確定排好了，這份 code 要比 49,995,000 次。

### 用一個 boolean 記住有沒有交換過

多一個變數 `swapped`。每輪開頭設回 false，有交換就設成 true。整輪跑完還是 false，代表這輪什麼都沒動，可以停：

```typescript
function bubbleSort(nums: number[]) {
  const n = nums.length;
  for (let i = 0; i < n; i++) {
    let swapped = false;
    for (let j = 0; j < n - 1 - i; j++) {   // 右邊已排好，每輪少比一個
      if (nums[j] > nums[j + 1]) {
        [nums[j], nums[j + 1]] = [nums[j + 1], nums[j]];
        swapped = true;
      }
    }
    if (!swapped) break;                    // 整輪都沒交換 = 已經排好了
  }
}
```

`[1, 2, 3, 4, 5]` 現在第 1 輪掃 4 次、一次都沒換，`swapped` 還是 false，直接 break，總共 4 次比較。最佳情況從 $O(n^2)$ 變成 $O(n)$ 就是這樣來的。

最糟情況沒有跟著變。完全倒序的 `[5, 4, 3, 2, 1]` 每一輪都在交換，`swapped` 永遠是 true，還是要跑滿，$O(n^2)$。

## 走一遍 `[2, 3, 1, 5, 4]`

上面那個播放器就是這組資料，走完 20 步：

```
每輪交換幾次：2 + 1 + 0 = 3 次
每輪比了幾次：4 + 3 + 2 = 9 次
排完：[1, 2, 3, 4, 5]
```

同一組資料，兩個版本並排：

| | 輪數 | 每輪比較 | 比較共 | 每輪交換 | 交換共 |
|---|---|---|---|---|---|
| 沒 `swapped` | 5 | 4 + 3 + 2 + 1 + 0 | 10 | 2 + 1 + 0 + 0 + 0 | 3 |
| 有 `swapped` | 3 | 4 + 3 + 2 | 9 | 2 + 1 + 0 | 3 |

交換次數兩邊一樣，都是 3 次。flag 省下來的只有「排好之後還在空掃」的那些比較，這組省 1 次，因為 n 才 5。第 4、5 輪就算跑了，元素也不會再動。

第 2 輪只換了一次（2 跟 1），第二大的 4 從頭到尾沒動過，它是第 1 輪 `5 > 4` 那次交換順便換到 index 3 的。Bubble sort 保證每輪結束時最右邊那格是對的，沒保證那個值是這一輪才搬過去的。

第 3 輪一次都沒換，`swapped` 是 false，直接 break。

## 對比其他排序

### 同一筆資料 `[2, 3, 1, 5, 4]` 丟給不同排序

| 演算法 | 這筆資料的表現 | 為什麼？ |
|--------|---------------|---------|
| Bubble Sort | 3 輪收工，比較 9 次、交換 3 次 | 第 3 輪 swapped 還是 false，提前結束 |
| Selection Sort | 跑滿 4 輪，比較 10 次 | 不看現狀，每輪都要掃過剩下的全部找最小 |
| Insertion Sort | 比較 6 次，最遠的元素往左插 2 格 | 幾乎排好的資料是它最擅長的場景 |
| Quick Sort | pivot 選最右邊的 4，左邊分到 3 個、右邊 1 個 | 這組還算平衡，但資料完全排好時同樣選法會退化成 $O(n^2)$ |

Bubble sort 不是最快的。同一組資料 insertion sort 只比 6 次，bubble sort 要比 9 次，因為 insertion sort 找到位置就停，bubble sort 得一輪一輪重掃。Bubble sort 贏 selection sort 的地方只有一個：它偵測得到「已經排好了」然後提前收工，selection sort 連這個都做不到。

## 穩定排序

相等的兩個元素，排完之後前後順序沒變，就叫穩定。

```
排序前: [(A, 3), (B, 1), (C, 3)]   按數字排
排好後: [(B, 1), (A, 3), (C, 3)]   A 還在 C 前面
```

Bubble sort 只在 `nums[j] > nums[j+1]` 時交換，相等就不動，所以 A 跟 C 永遠不會對調。把條件改成 `>=` 它就不穩定了，一個符號的差別。

但不是每個排序都這樣。

Bubble sort 只做相鄰交換。相鄰的兩個相等時不換，它們就永遠保持原順序，中間也不會有別的元素插進來。Insertion sort 也是一格一格往右推，同理。這兩個的穩定性確實由那個比較符號決定。

Selection sort 不一樣。它每輪找到最小值，直接跟前面那格對調，一次跨過中間所有元素。`[5a, 3, 5b, 1]` 第一輪把 1 換到最前面，5a 被丟到 index 3，跳過了 5b。打亂順序的是那次長距離的搬動，不是比較怎麼寫。把 `<` 改成 `<=` 一樣會發生。Quick sort 的 partition、heap sort 的 sift-down 都是同樣的情況。

所以穩定性有兩層：演算法只做相鄰移動的話，符號決定穩不穩；演算法會長距離搬動的話，怎麼寫都不穩定。

## 為什麼正式環境不用 bubble sort

5 個元素沒問題。50 個也還行。但 10,000 個呢？

n = 10,000 時，最糟要比較 (10,000 * 9,999) / 2 = 49,995,000 次。快五千萬次比較。

n = 100,000 時？最糟差不多 50 億次。

平均情況沒有好到哪去。隨機資料上只要還有任何一對相鄰的順序不對，`swapped` 就是 true，輪數還是接近 n。平均比較次數跟最糟同一個量級，一樣落在 50 億上下。

Quick Sort 處理同樣的 100,000 個元素，平均比較次數的教科書結果是 $2n \ln n$，也就是 100,000 * 23 ≈ 2,300,000 次。平均對平均，兩邊差了兩千倍以上。

所以主流語言的標準排序沒有一個用 Bubble Sort。Go 用 pdqsort，Python 用 TimSort，C++ 的 `std::sort` 用 Introsort，全部是 $O(n \log n)$。

## 複雜度

| | 值 |
|---|---|
| 最佳 | $O(n)$ — 已排好，一輪就結束 |
| 平均 | $O(n^2)$ |
| 最糟 | $O(n^2)$ — 完全倒序 |
| 空間 | $O(1)$ — 只用了幾個變數 |
| In-place | 是 |
| 穩定 | 是 |

最佳 $O(n)$ 來自 `swapped` 優化。沒有這個優化，最佳也是 $O(n^2)$。

## 總結

Bubble sort 教的是排序的本質：**比較 + 交換**。後面每一個排序演算法都在想辦法少比幾次、少換幾次，差別只在策略。

它還示範了一個到處都用得到的工程技巧：用一個 boolean 記住「這一輪有沒有做事」，沒做事就代表可以停了。已經排好的資料因此只掃一輪，$O(n)$；最糟情況該跑的還是要跑，$O(n^2)$ 不變。

至於它本身，10,000 個元素最糟要比將近五千萬次，沒有人會在正式環境用。
