# Lowbit

一個數字有好幾個 bit 是 1。你只想拿其中一個。怎麼拿？

---

## 問題

`110` 有兩個 1。bit 1 和 bit 2。

你不能同時用兩個 bit 來分組、做 mask、或當 index。你需要一個**只有單一 bit** 的數字。

最直覺的做法：一個一個找。

```go
mask := 1
for xorAll&mask == 0 {
    mask <<= 1 // 往左找，直到碰到 1
}
```

`110` 會先試 `001`，miss。再試 `010`，hit。拿到 bit 1。

這要一個迴圈。能不能一步到位？

---

## `n & (-n)` 一步到位

```go
lowbit := n & (-n)
```

`110 & (-110)` = `010`。一行，沒有迴圈。

但為什麼？

---

## 二補數

電腦用二補數存負數。`-n` 的算法：把 n 每個 bit 反轉，再加 1。

用 `n = 12`（`1100`）走一遍：

```
n       = 1100
反轉     = 0011
加 1     = 0100   ← 這就是 -n
```

反轉後，n 原本最右邊的 1（bit 2）變成了 0，它右邊的 0 全變成了 1。加 1 的進位從最右邊一路推上去，把那些 1 全部推回 0，直到推到原本那個位置，變回 1。

所以 `-n` 在最右邊的 1 那個位置跟 `n` 相同，但它左邊的所有 bit 全部相反。

AND 一下：

```
 n   = 1100
-n   = 0100
& --------
     = 0100   ← 左邊相反，AND 消掉。右邊都是 0。只剩最右邊的 1。
```

---

## 再走一個例子

`n = 40`（`101000`）：

```
n       = 101000
反轉     = 010111
加 1     = 011000   ← -n

  101000
& 011000
--------
  001000   ← bit 3，最右邊的 1
```

左邊 `10` vs `01`，AND 消掉。中間那個 1 兩邊都有，留下來。右邊三個 0 不影響。

---

## 不只最右邊

回到 [Single Number III](/problem/single-number-iii) 的問題。

`xorAll = 110`。bit 1 和 bit 2 都是 1。用哪個 bit 分組都行。

`xorAll & (-xorAll)` 取到 `010`（bit 1）。但 `100`（bit 2）也能正確分組。兩者的差別只是數字被分到不同組，但每組 XOR 出來的答案一樣正確。

lowbit 挑最右邊的 1，不是因為它唯一正確，而是因為它最好取。一行搞定，不需要迴圈。

---

## 其他用途

Lowbit 不只拿來分組。

### Fenwick Tree

Binary Indexed Tree 每次往上或往下跳多遠，由 lowbit 決定：

```go
// 往上更新：加 lowbit
func update(tree []int, i, delta, n int) {
    for ; i <= n; i += i & (-i) {
        tree[i] += delta
    }
}

// 往下查詢：減 lowbit
func query(tree []int, i int) int {
    sum := 0
    for ; i > 0; i -= i & (-i) {
        sum += tree[i]
    }
    return sum
}
```

`i = 6`（`110`）：lowbit = `010` = 2，跳到 8。
`i = 7`（`111`）：lowbit = `001` = 1，減到 6，再減到 4，再減到 0。

每一步的跳躍距離都由最低位的 1 決定。這就是 Fenwick Tree 能做到 $O(\log n)$ 的原因。

---

## 速查

| 操作 | 效果 | 例子 |
|------|------|------|
| `n & (-n)` | 取最低位的 1 | `1100 → 0100` |
| `n & (n-1)` | 消最低位的 1 | `1100 → 1000` |

一個把最低位的 1 取出來，一個把它消掉，剛好互補。
