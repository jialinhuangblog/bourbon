# Radix Sort

[Counting Sort](/concept/counting-sort) 排全班成績很快：準備 101 個桶子標上 0 到 100，每個人的分數丟進自己那個桶，再從 0 號桶開始倒出來就好了。

換成排年薪就不行。年薪可能到 10 億，桶子得開 10 億個，一個桶算 8 bytes 就要 8 GB 記憶體。

可是 10 億寫出來只有 10 位數：`1000000000`。每一位都只有 0 到 9 十種可能。

所以換個做法：不要一次排整個數字，改成一位一位排，每一輪只需要十個桶。

這就是 radix sort。

---

## 先試最直覺的：從百位開始

排數字的直覺是先看最大的那一位。拿 `[329, 355, 320]` 試，每一輪都照當時看的那一位把整個陣列重排一次。

```
一開始              [329, 355, 320]
排百位：3、3、3      → [329, 355, 320]   三個都一樣，不動
排十位：2、5、2      → [320, 329, 355]
排個位：0、5、9      → [320, 355, 329]
```

排完 329 落在 355 後面，錯了。

錯在最後那一輪。排個位會照個位把整個陣列重排，329 的個位是 9 比 355 的 5 大，就被放到後面。前面兩輪排好的百位十位，被最後這一輪重排掉。

---

## 反過來，從個位開始

同一組數字，順序倒過來：

```
一開始              [329, 355, 320]
排個位：9、5、0      → [320, 355, 329]
排十位：2、5、2      → [320, 329, 355]
排百位：3、3、3      → [320, 329, 355]
```

這次對了。道理同一條反過來用：最後排的那一位影響最大，所以最高位要留到最後。

十位那輪有個地方要看仔細。320 跟 329 的十位都是 2，這一輪分不出誰在前面。它們排完是 320 在前，因為個位那輪已經把 320（個位 0）放在 329（個位 9）前面，而排十位的時候沒有調動這兩個的相對順序。

先把低位排好，等高位平手的時候，直接沿用低位排出來的順序。

---

## 這兩個方向的名字

從個位往上排叫 **LSD radix sort**。LSD 是 Least Significant Digit，「最不影響數值大小的那一位」，329 的個位是 9 只代表 9。

從最高位往下排叫 **MSD**，Most Significant Digit，329 的百位是 3 代表 300。

上面那個錯誤版本不算真正的 MSD。MSD 照百位分完堆之後，堆跟堆就不能再放回去一起排了：

```
3 堆 → [329, 355]
4 堆 → [436, 457]
```

要是把這四個照十位一起重排，會變成 `329(2)、436(3)、355(5)、457(5)`，436 跑到 355 前面，百位排出來的順序就沒了。

所以 MSD 第二輪起是「每一堆各排一次」。程式要記住還有哪幾堆沒處理、每堆從哪到哪，寫成遞迴。而且每處理一堆都要走一遍那十格 `count`，堆縮到剩兩三個元素時，十格的成本比排序本身還大，實際的實作會在這時改用 insertion sort 收尾。

MSD 的好處是能提早停。排字串最明顯，`apple` 跟 `zebra` 第一個字母就分開了，後面四個字母不用讀。

LSD 不用分堆，每一輪掃過整個陣列就好，兩層迴圈寫完。以下都講 LSD。

---

## 每一輪用什麼排？

每一輪只看一位，那一位只有 0 到 9 十種值，十個桶子數一數就排好，正是 counting sort 最擅長的場景。

但要用 counting sort 的**穩定版**。穩定的意思是：這一位相同的兩個元素，排完之後的前後順序跟排之前一樣。剛才 320 跟 329 在十位那輪沒有被對調，就是穩定。

要是內層不穩定，排十位的時候把 320 跟 329 對調成 `[329, 320, 355]`，個位那輪的成果就沒了，最後結果會錯。LSD radix sort 能不能成立，全靠內層排序穩不穩定。

---

## 範例資料 `[329, 457, 657, 839, 436, 720, 355]`

七個數字都是三位數，所以跑三輪。這組每一輪都有好幾個元素在那一位上撞在一起，正好拿來看穩定性：第 2 輪的十位有三個 5（355、457、657），第 3 輪的百位有兩個 3（329、355）跟兩個 4（436、457）。

位數不齊也沒問題，例如 45 跟 802 混在一起。取位數的算式 `(v / exp) % 10` 在 `exp` 超過該數的位數時算出來自然是 0，等於高位自動補 0。示範資料選同樣長度，是為了讓演示裡的長條高度可以互相比較。

---

## 程式碼

自己拖，或按播放。上排是 `nums`，橘色那根是正在讀位數的元素。下排在計數階段是 `count` 的十格，在放置階段換成 `output`，左邊的標題會寫這一輪看的是哪一位。下排裝的是 0 到 7 這種小數字，長條幾乎貼著地，那一排看數字就好。

<div data-algo-viz="radix-sort" data-input="329,457,657,839,436,720,355"></div>

```typescript
function radixSort(nums: number[]) {
  let max = nums[0];
  for (const v of nums) {
    if (v > max) max = v;
  }
  // 個位、十位、百位…
  for (let exp = 1; Math.floor(max / exp) > 0; exp *= 10) {
    countingSortByDigit(nums, exp);
  }
}

function countingSortByDigit(nums: number[], exp: number) {
  const n = nums.length;
  const output = new Array<number>(n);
  // 十格，對應 digit 0~9
  const count = new Array<number>(10).fill(0);

  // 這一位是幾，那一格就加一
  for (const v of nums) {
    const digit = Math.floor(v / exp) % 10;
    count[digit]++;
  }
  // 累加成前綴和
  for (let i = 1; i < 10; i++) {
    count[i] += count[i - 1];
  }
  // 從後往前放，維持穩定
  for (let i = n - 1; i >= 0; i--) {
    const digit = Math.floor(nums[i] / exp) % 10;
    count[digit]--;
    output[count[digit]] = nums[i];
  }
  nums.splice(0, n, ...output);
}
```

`exp` 是「現在看哪一位」的開關：`exp = 1` 時 `(329 / 1) % 10 = 9` 取到個位，`exp = 10` 時 `(329 / 10) % 10 = 2` 取到十位。外層迴圈讓它一路乘 10，除到 0 為止。

`countingSortByDigit` 分三段。

**數。** 第 1 輪七個數字的個位是 9、7、7、9、6、0、5，數完 `count = [1, 0, 0, 0, 0, 1, 1, 2, 0, 2]`。

**累加。** 每一格加上前一格，變成 `[1, 1, 1, 1, 1, 2, 3, 5, 5, 7]`。現在 `count[7] = 5` 的意思換成「個位小於等於 7 的有 5 個」，也就是個位是 7 的那些數字，最後一個要放在 index 4。累加算出來的是位置，不再是次數。

**從後往前放。** 走到一個元素就把它那格的 `count` 減一，減完的值就是它在 `output` 的 index。從最右邊的 355 開始：個位 5，`count[5]` 從 2 減成 1，355 放進 `output[1]`。接著 720：個位 0，`count[0]` 從 1 減成 0，720 放進 `output[0]`。一路走回最左邊就填滿了。

---

## 走一遍 `[329, 457, 657, 839, 436, 720, 355]`

上面那個播放器跑的就是這組資料，走完 53 步：

```
輪數：3 輪（exp = 1、10、100）
每輪看的位數：個位 → 十位 → 百位
取位數的次數：每輪 14 次（計數 7 次 + 放置 7 次），3 輪共 42 次
排完：[329, 355, 436, 457, 657, 720, 839]
```

十位那輪，`355`、`457`、`657` 的十位都是 5，放進 `output` 之後先後跟進來時一樣，這就是穩定。

還有一件事在播放器上看得到：每輪結束時整個陣列都是「這一位排好」的狀態，但深色（已定案）要等第三輪結束才出現。前兩輪的結果還會被更高的位重排，中途沒有任何一格是定案的。

---

## 從後往前，就是穩定性的來源

累加之後的 `count[d]` 給的是「digit 等於 d 的那批元素，最後一個放在哪」。從後往前配位置，原本在右邊的先拿到後面的 index，原本在左邊的後拿到前面的 index，原來的先後就被還原了。

改成從前往後會怎樣？第 3 輪百位是 3 的有 329 跟 355，累加後 `count[3] = 2`。從前往後走，先遇到 329，`count[3]` 減成 1，329 進 `output[1]`；再遇到 355，`count[3]` 減成 0，355 進 `output[0]`。

329 原本在 355 前面，現在跑到後面。整份輸出變成 `[355, 329, 457, 436, 657, 720, 839]`，前四格全錯。

---

## 說它是 $O(n)$，前提是什麼

n、d、k 各是什麼：

- **n**：有幾筆資料
- **d**：每筆有幾位數
- **k**：每一位有幾種值，十進制就是 10

一輪要做的工作是 `2n + k`：讀 n 次位數來計數、再讀 n 次放進 `output`、走一遍 `count` 的 k 格。跑 d 輪就是 `d × (2n + k)`。

拿實際數字代。排 0 到 999 的號碼，每筆都是三位數，所以 d = 3、k = 10：

| 幾筆資料 n | 一輪 2n + 10 | 三輪合計 |
|---:|---:|---:|
| 1,000 | 2,010 | 6,030 |
| 10,000 | 20,010 | 60,030 |
| 100,000 | 200,010 | 600,030 |

n 乘 10，工作量也乘 10。這就是線性，$O(n)$。

線性成立是因為 d 一直是 3。d 由值域決定，不由資料量決定：只要號碼都在 0 到 999 之間，來 1,000 筆是三位數，來 10 萬筆還是三位數。

### d 什麼時候會跟著 n 長

要求每筆都不重複的話，三位數最多只裝得下 1,000 個（000 到 999），第 1,001 個就得改用四位數。

| 要幾個相異數字 | 至少要幾位 d |
|---:|---:|
| 100 | 2 |
| 1,000 | 3 |
| 10,000 | 4 |
| 1,000,000 | 6 |

n 乘 10，d 就加 1。這個關係寫出來就是 $\log_{10} n$。

代回 `d × (2n + 10)`：

| 幾筆資料 n | d | 合計 | 比上一列 |
|---:|---:|---:|---:|
| 1,000 | 3 | 6,030 | |
| 10,000 | 4 | 80,040 | 13.3 倍 |
| 100,000 | 5 | 1,000,050 | 12.5 倍 |

n 乘 10，工作量卻是 13 倍、12.5 倍，每次都比 10 倍多一點。多出來的就是 d 加的那一輪。這個形狀就是 $O(n \log n)$，跟 quick sort 同一級。

所以 radix sort 的 $O(n)$ 不是無條件的。前提是 d 固定，也就是值域先被釘死：32 bits 整數最大 2147483647，永遠在 10 位數以內，100 萬筆是這樣，1 億筆也是這樣。

### 那為什麼比較排序做不到 $O(n)$

比較排序有一條 $\Omega(n \log n)$ 的 lower bound，管的是「只能靠比較取得資訊」的演算法。radix sort 從頭到尾沒有比較過任何兩個數字，只是讀位數跟數數，所以不受它約束。

不過 d = 10 這個常數也不小。Quick sort 排一百萬筆大約 $\log_2 n \approx 20$ 層，radix sort 是 10 輪，但每輪要多讀一遍加多寫一遍。兩邊每一步做的工作不一樣重，光看 10 跟 20 比不出誰快，實際誰贏要量。

## 負數跟浮點數怎麼辦？

上面那份程式碼只吃非負整數，`(v / exp) % 10` 碰到負數會算出負的 digit，`count[-3]` 直接出錯。

負數有兩種常見做法：整份平移（全部加上 `-min` 變成非負，排完再減回去，代價是位數可能多一位），或按正負拆兩份分開排。

浮點數要先做 bit 層的轉換：正數把 sign bit 改成 1，負數整個 32 bits 或 64 bits 反轉，轉完當成無號整數排，排完再轉回來。NaN 跟 `-0.0` 要另外處理。

每一種型別都要寫一段專屬的轉換，這也是下一節的第一個理由。

---

## 為什麼標準函式庫不用 radix sort

**型別不通用。** 上一節那些轉換每種型別都要各寫一份，而標準函式庫的 sort 只要求一個比較函式，任何型別都塞得進去。

**常數大。** 每輪要開一個跟原陣列一樣長的 `output`，讀兩遍 `nums`、走一遍 `count`，再把 `output` 複製回去。

**對快取不友善。** 快取（cache）是 CPU 旁邊一小塊很快的記憶體，讀資料時會把附近那一整塊一起帶進來，連續讀常常找得到，跳著讀常常找不到，找不到就得等主記憶體。radix sort 的放置階段是跳著寫的：相鄰兩個元素只要 digit 不同，就寫到 `output` 的兩個很遠的位置。Quick sort 的 partition 是從頭掃到尾，命中率好得多。

標準函式庫要的是一份放到哪都不會太差的實作。radix sort 剩下的位置是自己挑場景用：資料是整數、位數固定、值域先知道。

## 複雜度

| | 值 |
|---|---|
| 最佳 / 平均 / 最糟 | $O(d \cdot (n + k))$ |
| 空間 | $O(n + k)$ |
| In-place | 否 |
| 穩定 | 是 |

d = 位數，k = 每一位有幾種值。基數換大可以少跑幾輪，但每輪的 `count` 會變長。實務常見 256 進制：一個 byte 一輪，32 bits 整數 4 輪，`count` 開 256 格。

跟 counting sort 的分工：counting sort 是零件，值域小的時候直接用；radix sort 把一個大值域切成好幾輪小值域的 counting sort，值域大但位數固定的時候用。

---

## 面試考什麼？

直接考的題幾乎沒有。被問「排序的 lower bound 是什麼」，可以答「只靠比較的演算法是 $\Omega(n \log n)$，radix sort 不靠比較，值域固定的前提下可以做到 $O(n)$」。

---

## 總結

Counting sort 怕值域大，radix sort 把大值域切成一位一位的小值域，10 位數就跑 10 輪，每輪 $O(n)$。

它成立要三個前提：資料是整數（或能轉成整數）、位數固定、每一輪的內層排序穩定。三個少一個，它就用不上或者會排錯。
