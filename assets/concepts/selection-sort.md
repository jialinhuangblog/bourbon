# Selection Sort

Bubble Sort 有一個小聰明：如果某一輪沒有交換，它知道陣列排好了，提前收工。

Selection Sort 連這種判斷都沒有。

給它一個完全排好的 `[1, 2, 3, 4, 5]`，它照樣跑滿 4 輪，每輪掃描到最後一格，做完 10 次比較。值一個都沒變，4 次跟自己交換也照做。

---

## 想法

體育課。老師要小朋友從矮排到高。

老師的方法：看一遍所有人，找到最矮的那個，叫他站到最左邊。然後看剩下的人，找到最矮的，站到第二個位置。一直重複。

不管你們本來站得怎樣。老師每次都從還沒站好的第一個看到最後一個。找到最矮的。放好。下一個。

---

## 範例資料 `[64, 25, 12, 22, 90, 33, 45, 11]`

這組資料完全亂序。最小值 11 在最右邊，開頭的 64 是第二大。

第 1 輪就有一次跨越整個陣列的 swap：11 從最右邊搬到最左邊，64 從最左邊搬到最右邊。

掃描量也看得出規律。每一輪的比較次數是 7、6、5、4、3、2、1，只跟輪次有關。把這組資料換成已經排好的，比較次數還是 7、6、5、4、3、2、1。

對比：**bubble sort 碰到幾乎排好的資料，swapped=false 就收工。** 這組資料讓 bubble sort 也很痛苦，沒有早退機會。

對比：**insertion sort 碰到這組資料，1 號元素要插到最前面，移動量很大。** 但 insertion sort 至少會利用「前面已排好」的資訊來決定插入位置。Selection sort 不利用任何已知資訊。

這組資料對 selection sort 不好也不壞。比較次數跟輸入完全無關，永遠是 $n(n-1)/2$；會跟著輸入變的只有 swap 裡真正搬動了東西的那幾次。

## 動畫

自己拖，或按播放。深色是已經排好的部分，藍色是目前記住的最小值，橘色是這一步正在比的那格。圖例裡的「空出來的位置」在這裡不會出現，selection sort 全程原地交換，沒有元素被拿在手上。

<div data-algo-viz="selection-sort" data-input="64,25,12,22,90,33,45,11"></div>

每一輪做一件事：在未排序的 range 裡找最小值，交換到已排好的那一頭。找的時候只更新 `minIdx`，不動陣列。

## 程式碼

```typescript
function selectionSort(nums: number[]) {
  for (let i = 0; i < nums.length - 1; i++) {
    let minIdx = i;                          // 先假設 i 就是最小的
    for (let j = i + 1; j < nums.length; j++) {
      if (nums[j] < nums[minIdx]) {          // 比目前記住的還小？
        minIdx = j;                          // 記住最小的在哪
      }
    }
    [nums[i], nums[minIdx]] = [nums[minIdx], nums[i]];   // 整輪只交換這一次
  }
}
```

### 外層迴圈

`for i := 0; i < len(nums)-1; i++`。i 代表「這次要填第幾格」。第 0 格放最小的，第 1 格放第二小的。

停在 `len(nums)-1` 而不是 `len(nums)`，是因為前面 $n-1$ 格都填好之後，剩下的那一格只有一個候選人，一定是最大的。多跑那一輪只會跟自己交換一次，什麼都不會變。

### 內層迴圈

`for j := i+1; j < len(nums); j++`。從 i+1 掃描到最後，找出最小值的 index。

它不是找到一個小的就交換，而是掃描完全部、記住最小的在哪（`minIdx`），最後才做一次 swap。

**整輪只做一次 swap。** 這是 selection sort 跟 bubble sort 最大的差別。Bubble sort 每碰到一對逆序就交換，一輪可能 swap 很多次。Selection sort 先掃描完全部、記住最小的在哪，最後只交換一次。

### 交換

`nums[i], nums[minIdx] = nums[minIdx], nums[i]`。把找到的最小值放到位置 i。

如果 `minIdx == i`，等於跟自己交換。沒副作用，只是浪費一次 swap。

## 走一遍 `[64, 25, 12, 22, 90, 33, 45, 11]`

上面那個播放器就是這組資料，走完 52 步：

```
比較次數：7 + 6 + 5 + 4 + 3 + 2 + 1 = 28 次
swap 次數：7 次（其中 1 次是跟自己交換）
排完：[11, 12, 22, 25, 33, 45, 64, 90]
```

比較次數 7、6、5、4、3、2、1 只跟輪次有關，跟資料長什麼樣無關。這組換成已經排好的 `[11, 12, 22, 25, 33, 45, 64, 90]`，還是比 28 次。

第 1 輪，11 從最右邊直接搬到最左邊，64 被丟到最後面，一次跨過整個陣列。這種長距離的搬動就是它不穩定的原因。

第 4 輪的 swap 是 25 跟自己交換，`minIdx == i` 時那行還是照執行。要省掉得多寫一個 `if minIdx != i`，代價是每輪多一次判斷（這裡 7 次），省下的是自我交換那幾輪的寫入（這裡 1 輪）。int 陣列不划算，交換成本高的東西才划算。

## 跟 Bubble Sort 逐項比較

同一筆資料 `[64, 25, 12, 22, 90, 33, 45, 11]`：

| | Bubble Sort | Selection Sort |
|---|---|---|
| 比較次數 | 28 | 28 |
| swap 次數 | 上限 28 次，這組實際 16 次（等於逆序對數） | 7 次（每輪一次，其中 1 次跟自己交換） |
| 能提前結束嗎 | 能，某輪 swapped=false 就停 | 不能，永遠跑滿 |
| 給它排好的資料 | $O(n)$ 一輪收工 | $O(n^2)$ 照跑 |

Selection sort 的 swap 次數永遠是 $n-1$，跟資料多亂無關。Bubble sort 的 swap 次數等於逆序對數，最壞到 $n(n-1)/2$。

### swap 少什麼時候真的有價值

100 筆資料，bubble sort 最壞要 swap 4,950 次，selection sort 固定 99 次，差 50 倍。但這 50 倍在 RAM 上跑不出來。swap 是寫記憶體，comparison 是讀記憶體，而 RAM 讀跟寫一樣快，所以少寫那 4,851 次也省不到時間。

得換到寫比讀貴很多的硬體。EEPROM 是其中一種：斷電之後資料還在，代價是每一格寫的次數有上限，而且寫一次比讀一次慢兩個數量級。Microchip 24LC256 這顆 I2C EEPROM 的資料表寫著每格耐久 1,000,000 次、寫入週期 `TWC` 最大 5 ms（page mode，25°C，5.5V）。

把那 100 筆資料存在這顆晶片上原地排序。一次 swap 動兩格，兩格各被寫一次：

| | swap 次數 | 寫入次數 | 攤到 100 格 | 一百萬次預算能排幾趟 |
|---|---|---|---|---|
| Bubble Sort 最壞 | 4,950 | 9,900 | 每格 99 次 | 約 1 萬趟 |
| Selection Sort | 99 | 198 | 每格 2 次 | 約 50 萬趟 |

同一顆晶片，換個排序演算法，能用的次數差 50 倍。

那元素很大的話呢？搬一個 1 KB 的 struct，聽起來應該比搬 int 貴很多。現代語言不會真的搬那 1 KB，交換的是指標，8 bytes，跟交換 int 一樣快。所以在 RAM 裡，元素大小也救不回 selection sort 的這個優勢。

selection sort 也不是寫入次數的理論最少。**cycle sort** 才是，每個值不是留在原位一次都不寫，就是只寫一次到定位。Wikipedia 的說法是「theoretically optimal in terms of the total number of writes to the original array」。代價是比較次數更多、實作更繁瑣。面試被問「哪個排序寫入最少」，答 cycle sort 比答 selection sort 準。

## 為什麼不穩定？

穩定排序：相同值的元素，排完之後維持原本的相對順序。

看這個例子：`[5a, 3, 5b, 1]`。5a 和 5b 值相同，5a 在前面。

```
第 1 輪：找最小 = 1（位置 3），swap(位置 0, 位置 3)
  [1, 3, 5b, 5a]  ← 5a 跑到 5b 後面了！
```

問題出在長距離 swap。5a 從位置 0 直接跳到位置 3，越過了 5b。一次 swap 就打亂了相對順序。

Bubble sort 不會有這個問題。它只做相鄰交換，相同值不交換（`>` 不是 `>=`），所以穩定。

Insertion sort 也是穩定的。它把元素一格一格往右推，相同值不推（`>` 不是 `>=`），所以不會改變相對順序。

Selection sort 是三個 $O(n^2)$ 排序裡唯一不穩定的。

## 複雜度

| | 值 |
|---|---|
| 最佳 | $O(n^2)$ — 排好了也跑滿 |
| 平均 | $O(n^2)$ |
| 最糟 | $O(n^2)$ |
| 空間 | $O(1)$ |
| In-place | 是 |
| 穩定 | 否 |
| swap 次數 | $O(n)$ — 永遠 |

三種情況都是 $O(n^2)$。沒有捷徑，沒有早退，沒有最佳情況。

只有 swap 次數不一樣：永遠 $O(n)$。

---

## 什麼時候用？

幾乎不用。

面試考排序觀念時會出現。LeetCode 不會有題目需要手寫 selection sort。

但理解它之後，比較看得出為什麼 insertion sort 是更好的選擇：同樣是 $O(n^2)$、$O(1)$ 空間、簡單好寫，但 insertion sort 至少會適應輸入，幾乎排好的資料跑 $O(n)$。

---

## 總結

Selection sort 不管輸入長什麼樣，每輪都從未排序的第一格掃描到最後一格。

它做的事情很直覺：找最小的，放前面。再找最小的，放前面。

代價是：就算資料已經排好，它照樣跑 $n(n-1)/2$ 次比較。連 bubble sort 都有提前結束的機制，它沒有。

唯一的優勢是 swap 次數少，固定 $n-1$ 次。在現代 RAM 裡沒什麼意義，在 EEPROM 這類寫入昂貴的硬體上才算得出差別。真要把寫入次數壓到理論最少，答案是 cycle sort 不是它。
