# Two's Complement

電腦怎麼存負數？

直覺想法：拿最高位當正負號。`0100` 是 4，`1100` 是 -4。

麻煩在於：`0000` 是 0，`1000` 也是 -0，出現兩個零。加法也會壞：`0100 + 1100 = 10000`，不是 0。硬體得為符號位另外做一套加法器。

能不能讓負數的表示法「剛好」讓普通加法就得到正確結果？

---

## 取反加 1

把 4 變成 -4：

```
4       = 0100
取反     = 1011
加 1     = 1100   ← 這就是 -4
```

驗證：`0100 + 1100 = 10000`。4 bit 只留低 4 位，`0000`。4 + (-4) = 0。正確。

溢出的第 5 位丟掉，剩下 4 位剛好歸零。固定寬度讓正負數相加自然對齊到 0。

這就是 two's complement（二補數）。

---

## 為什麼溢出要丟掉？

因為硬體只有固定寬度。4-bit 系統只有 4 個位置存資料。第 5 位超出範圍，硬體直接丟掉。

8-bit 一樣：

```
 4 = 00000100
-4 = 11111100

00000100 + 11111100 = 100000000（9 位）
第 9 位丟掉 → 00000000
```

64-bit 溢在第 65 位。不管幾 bit，機制完全一樣。

Two's complement 就是圍繞這件事設計的：取反加 1 之後，正數加負數剛好溢位歸零。這是刻意設計的結果，取反加 1 這個規則就是為了讓溢位自動修正答案。

---

## -1 長什麼樣？

```
1       = 0001
取反     = 1110
加 1     = 1111   ← -1
```

-1 是全部都 1。4-bit 是 `1111`，8-bit 是 `11111111`，64-bit 是 64 個 1。

這也合理：`0001 + 1111 = 10000`，溢位丟掉，`0000`。1 + (-1) = 0。

---

## 範圍不對稱

64-bit signed integer 的範圍：$-2^{63}$ 到 $2^{63} - 1$。

正數少一格，負數多一格。為什麼？

正數那邊：`000...001` 到 `011...111`，最大是 $2^{63} - 1$。要減 1 是因為 `000...000` 被 0 佔走了。

負數那邊：`100...000` 到 `111...111`。最小的 `100...000` 取反加 1 回來還是 $2^{63}$，所以它代表 $-2^{63}$。

0 的表示是 `000...000`，算在正數那邊，不佔負數的位置。所以負數不用減 1。

$2^{63}$ 個負數 + $2^{63} - 1$ 個正數 + 1 個零 = $2^{64}$ 個值。剛好填滿 64 bit。

---

## Unsigned vs Signed

同一組 bit，CPU 提供兩種解讀：

| | unsigned | signed |
|---|---|---|
| `11111111` (8-bit) | 255 | -1 |
| `10000000` (8-bit) | 128 | -128 |
| 範圍 (8-bit) | 0 到 255 | -128 到 127 |
| 範圍 (64-bit) | 0 到 $2^{64} - 1$ | $-2^{63}$ 到 $2^{63} - 1$ |

記憶體裡的 bit 完全一樣，差別只在用哪個指令去讀。

這不是 OS 決定的，是 CPU 層級的事。CPU 的 ALU（Arithmetic Logic Unit，算術邏輯單元，做加減與比大小的電路）對同一組 bit 提供兩種解讀方式。程式語言 / 編譯器告訴 CPU 要用哪種指令。

---

## 加法只有一套電路

Unsigned 和 signed 的加減法，bit 操作完全一樣。Two's complement 這樣設計，硬體就不用為兩種各做一套加法電路。

差別在結果的判斷。CPU 做完每次運算，同時設好一組 status flags：

| Flag | 全名 | 意義 |
|---|---|---|
| CF | Carry Flag | 最高位有進位溢出 |
| OF | Overflow Flag | signed 結果符號不對 |
| SF | Sign Flag | 結果的最高位（符號位） |
| ZF | Zero Flag | 結果為零 |

### Carry Flag

```
  11111111    (unsigned: 255)
+ 00000001    (unsigned: 1)
-----------
 100000000    第 9 位溢出 → CF = 1
```

Unsigned 角度：255 + 1 = 256，超過 8-bit 能表示的範圍。CF 告訴你「溢了」。

### Overflow Flag

```
  01111111    (signed: 127)
+ 00000001    (signed: 1)
-----------
  10000000    signed 讀出 -128 → OF = 1
```

兩個正數加出負數，明顯錯了。OF 告訴你「signed 溢了」。

同一次加法，CPU 同時算出 CF 和 OF。要看哪個 flag 不是臨時選的：編譯器照變數型別（signed 或 unsigned）挑好指令，指令自己去看對應的那個 flag。下一節的跳轉指令就是這樣分工。

---

## 條件跳轉：同樣的 bit，不同的判斷

x86 的 `cmp a, b` 做的事是 `a - b`，然後設 flags。接下來用哪個跳轉指令，決定 unsigned 還是 signed 比較：

| 指令 | 全名 | 意思 | 看哪個 flag |
|---|---|---|---|
| JA | Jump if Above | a > b (unsigned) | CF=0 且 ZF=0 |
| JB | Jump if Below | a < b (unsigned) | CF=1 |
| JG | Jump if Greater | a > b (signed) | OF=SF 且 ZF=0 |
| JL | Jump if Less | a < b (signed) | OF!=SF |

同一次 `cmp`，同樣的 bit，JA 和 JG 可能跳去不同地方：

```
cmp 11111111, 00000001

unsigned: 255 vs 1 → JA 跳（255 > 1）
signed:    -1 vs 1 → JL 跳（-1 < 1）
```

硬體是同一套，解讀不同。

## 跟 Lowbit 的關係

[Lowbit](/concept/lowbit) 的核心是 `n & (-n)`。`-n` 就是 two's complement：取反加 1。

```
n    = 1100
-n   = 0100

  1100
& 0100
------
  0100   ← 最右邊的 1
```

取反讓左邊所有 bit 相反，AND 消掉。加 1 的進位在最右邊的 1 停住，兩邊在那個位置都是 1，AND 留下。

所以 lowbit 全靠 two's complement。而 lowbit 又是 Fenwick Tree 的基礎，也是 [Single Number III](/problem/single-number-iii) 那個 $O(1)$ 空間解法的關鍵。
