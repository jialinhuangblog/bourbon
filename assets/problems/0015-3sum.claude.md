給一個陣列，找出所有三個數加起來等於 0 的組合，不能重複。

---

## 解法一：暴力（三層迴圈）

三層迴圈。每個人都想得到。

```typescript
function threeSum(nums: number[]): number[][] {
    const n = nums.length;
    const seen = new Set<string>();
    const result: number[][] = [];
    for (let i = 0; i < n; i++) {
        for (let j = i + 1; j < n; j++) {
            for (let k = j + 1; k < n; k++) {
                if (nums[i] + nums[j] + nums[k] === 0) {
                    const tri = [nums[i], nums[j], nums[k]].sort((a, b) => a - b); // 排序才能 dedup
                    const key = tri.join(',');
                    if (!seen.has(key)) {
                        seen.add(key);
                        result.push(tri);
                    }
                }
            }
        }
    }
    return result;
}
```

- **Time: $O(n^3)$**
- Space: O(n) — 用 map dedup

}

## 解法二：排序＋雙指針

3Sum 本質是什麼？固定一個數 `nums[i]`，在剩下的數裡找兩個加起來等於 `-nums[i]`。就是 Two Sum。

Two Sum 用 hash map 是 O(n)。但這題要 dedup。hash map 的 dedup 很煩，得排序、比較、塞 set。

換個思路。先排序整個陣列。排完序之後，重複的數字靠在一起，跳過很容易。然後對每個 `nums[i]`，用雙指標在右邊找 Two Sum。

```typescript
function threeSum(nums: number[]): number[][] {
    nums.sort((a, b) => a - b);              // 先排序
    const result: number[][] = [];
    for (let i = 0; i < nums.length - 2; i++) {
        if (nums[i] > 0) break;             // 最小的都正了，不可能湊零
        if (i > 0 && nums[i] === nums[i - 1]) continue; // 跳過重複
        let lo = i + 1, hi = nums.length - 1;
        while (lo < hi) {
            const sum = nums[i] + nums[lo] + nums[hi];
            if (sum < 0) {
                lo++;
            } else if (sum > 0) {
                hi--;
            } else {
                result.push([nums[i], nums[lo], nums[hi]]);
                lo++;
                while (lo < hi && nums[lo] === nums[lo - 1]) lo++; // 跳過重複
            }
        }
    }
    return result;
}
```

- Time: $O(n^2)$ — 外層 O(n)，內層雙指標 O(n)
- Space: O(1) — 不算輸出的話

<details>
<summary>Go 版本</summary>

```go
func threeSum(nums []int) [][]int {
    sort.Ints(nums)                          // 先排序
    var result [][]int
    for i := 0; i < len(nums)-2; i++ {
        if nums[i] > 0 { break }            // 最小的數都 > 0，不可能湊出 0
        if i > 0 && nums[i] == nums[i-1] {  // 跟上一個一樣？跳過，避免重複
            continue
        }
        lo, hi := i+1, len(nums)-1
        for lo < hi {
            sum := nums[i] + nums[lo] + nums[hi]
            if sum < 0 {
                lo++                         // 太小，左邊往右
            } else if sum > 0 {
                hi--                         // 太大，右邊往左
            } else {
                result = append(result, []int{nums[i], nums[lo], nums[hi]})
                lo++
                for lo < hi && nums[lo] == nums[lo-1] { // 跳過重複
                    lo++
                }
            }
        }
    }
    return result
}
```

</details>

從 $O(n^3)$ 降到 $O(n^2)$。n = 3000 只要 900 萬次。過了。

### 走一遍範例

`nums = [-1,0,1,2,-1,-4]` 排序後變成 `[-4,-1,-1,0,1,2]`，index 0 到 5。

**i = 0（nums[i] = -4）**

| lo | hi | sum | 動作 |
|---|---|---|---|
| 1 | 5 | -4-1+2 = -3 | 小於 0，lo++ |
| 2 | 5 | -4-1+2 = -3 | 小於 0，lo++ |
| 3 | 5 | -4+0+2 = -2 | 小於 0，lo++ |
| 4 | 5 | -4+1+2 = -1 | 小於 0，lo++ |
| 5 | 5 | — | lo == hi，結束 |

**i = 1（nums[i] = -1）**

| lo | hi | sum | 動作 |
|---|---|---|---|
| 2 | 5 | -1-1+2 = 0 | 找到 `[-1,-1,2]`，lo++（nums[3]≠nums[2]，不用再跳） |
| 3 | 5 | -1+0+2 = 1 | 大於 0，hi-- |
| 3 | 4 | -1+0+1 = 0 | 找到 `[-1,0,1]`，lo++ |
| 4 | 4 | — | lo == hi，結束 |

**i = 2（nums[i] = -1）**
跟 nums[1] 一樣，dedup 掉，跳過。

**i = 3（nums[i] = 0）**

| lo | hi | sum | 動作 |
|---|---|---|---|
| 4 | 5 | 0+1+2 = 3 | 大於 0，hi-- |
| 4 | 4 | — | lo == hi，結束 |

四輪跑完，結果是 `[[-1,-1,2],[-1,0,1]]`，跟題目範例對上。

**能不能更好？**

能不能 O(n log n)？不能。

想像所有數字都不同。任意三個數的組合有 $C(n,3) = \dfrac{n \times (n-1) \times (n-2)}{3 \times 2 \times 1} \approx \dfrac{n^3}{6}$ 種，這是暴力解要看過的量級。但答案最多能有幾組不用看到 $n^3$：想像陣列是一串連續整數，`nums = [-m, ..., -1, 0, 1, ..., m]`，n = 2m+1 個數，兩兩不同。固定 `nums[i] = v`，要在剩下的數裡找兩個加起來等於 `-v` 的 pair，這種 pair 大約有 $O(n)$ 組。n 個 `i` 各自貢獻 $O(n)$ 組答案，加起來就有 $O(n^2)$ 組三元組，而且陣列裡的數值兩兩不同，不會有兩組三元組的三個數字完全一樣，dedup 的時候一組都不會少。

演算法至少要把這 $O(n^2)$ 組答案都輸出出來，光是輸出就要 $O(n^2)$ 步，不可能比 $O(n^2)$ 快。

---

**Dedup 的三個地方，缺一不可：**

1. `if i > 0 && nums[i] == nums[i-1]` — 外層跳過重複的 `i`
2. `for lo < hi && nums[lo] == nums[lo-1]` — 找到答案後，左指標跳過重複
3. 排序本身 — 沒排序就沒辦法用 `==` 前一個來判斷重複

有人問：「右指標 `hi` 不用跳嗎？」不用。左邊跳了，右邊的重複自然會被左邊過濾掉。下一輪 `sum` 會不等於 0，`hi--` 自己會走。

---

## 結論

排序 + 雙指標。$O(n^2)$，這題的下界。Dedup 靠排序，不靠 set。
